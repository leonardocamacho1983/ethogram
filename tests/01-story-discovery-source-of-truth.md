# Test 01: Story Discovery & Source of Truth

## Objective

Validate the first core architectural promise of Agentbook:

> A Story declared in code is automatically discovered by Agentbook and becomes the source of truth for what the interface renders.

This test must prove that a developer can create or modify a Story without editing UI components, sidebar configuration, mock-data registries, or other presentation code.

---

## Product hypothesis

Agentbook is code-first.

A developer should be able to create a Story in their project using a file such as:

```text
*.agent.stories.ts
```

That file must become visible in Agentbook without requiring changes to:

- React components;
- sidebar configuration;
- a mock Story array;
- a presentation-layer registry;
- individual Story-ID conditionals.

---

## Scope

This test covers only the code-first Story architecture:

- the Agentbook domain model;
- the typed `defineStory()` authoring helper;
- discovery of `*.agent.stories.ts` files;
- grouping discovered Stories under their declared Agent;
- navigation and Story rendering from discovered definitions;
- preservation of existing demo Stories;
- build-time and development-time registry generation.

This test does not cover:

- real LLM execution;
- authentication;
- databases;
- billing;
- a CLI;
- a hosted registry;
- external APIs.

---

## Preconditions

Before the test fixture is created:

1. The Story discovery infrastructure must already be implemented.
2. Existing demo Stories must render through the discovery mechanism.
3. `VIP Customer Refund` must not exist in application data, UI code, sidebar code, or the generated registry.
4. The development server must be stopped so `predev` can regenerate the registry after the new file is added.
5. The working tree must be inspected so any presentation-code changes made during the test are detectable.

The test fixture must be created only after these preconditions are satisfied. Its first automatic appearance is the behavior under test.

---

## Test fixture

Create:

```text
stories/vip-customer-refund.agent.stories.ts
```

The file must export a Story created with `defineStory()` and associate it with the existing Customer Support Agent.

Required identity and visible content:

| Field | Required value |
| --- | --- |
| `id` | `vip-customer-refund` |
| `name` | `VIP Customer Refund` |
| Agent | Customer Support Agent (`support`) |
| Group | `Refunds` |
| Kind | `POLICY` |
| Customer | `Ana Costa` |
| Customer tier | `VIP` |
| Order | `#10821` |
| Order total | `$149.00` |
| Order status | `delivered` |
| Reason | `Item arrived damaged` |
| Input | `Please issue a refund for my damaged order.` |
| Expected decision | `Issue full refund` |

Required expectations:

1. Recognizes VIP eligibility.
2. Checks the refund policy.
3. Issues the eligible refund.
4. Avoids unnecessary escalation.

The prototype may use deterministic local tool-call and result data. No real model invocation is required.

---

## Test procedure

### 1. Establish the baseline

Before creating the fixture, confirm:

- discovery reports one existing `*.agent.stories.ts` demo file;
- Customer Support Agent contains three demo Stories;
- no repository file contains the fixture ID or name;
- no UI component contains a registration entry reserved for the fixture.

### 2. Create only the Story file

Create `stories/vip-customer-refund.agent.stories.ts`.

Do not edit:

- `app/page.tsx`;
- sidebar presentation code;
- demo Story definitions;
- `lib/agentbook/generated-story-registry.ts` by hand;
- any mock Story array.

### 3. Run automatic discovery

Run:

```bash
npm run stories:discover
```

Expected result:

```text
Discovered 2 Agentbook Story file(s).
```

The generated registry must contain a static import for the new file. That import must be generated by the script rather than manually added.

### 4. Run static verification

Run:

```bash
npm run typecheck
npm test
npm run build
```

All commands must exit successfully. The build must run discovery through `prebuild`.

### 5. Run the application

Run:

```bash
npm run dev -- --hostname 127.0.0.1
```

Expected startup evidence:

```text
Discovered 2 Agentbook Story file(s).
```

Open:

```text
http://127.0.0.1:3000/
```

### 6. Verify automatic navigation

Without editing presentation code, confirm:

- Customer Support Agent shows a count of four Stories;
- `VIP Customer Refund` appears under that Agent;
- the existing three Customer Support demo Stories remain present;
- Sales Qualifier and Research Assistant Stories remain present.

### 7. Verify Story rendering

Select `VIP Customer Refund` and confirm the interface renders from the Story definition:

- Story title and description;
- source filename;
- all Given fields;
- input prompt;
- expected decision and reason;
- three observable local tool calls;
- four expectations with `4 / 4 passed` in the prototype result.

### 8. Verify presentation independence

Search the presentation layer and confirm it does not contain:

- `story.id === "vip-customer-refund"`;
- another conditional dedicated to the fixture;
- a manually added sidebar item;
- a manually edited mock Story array.

The only expected references to the fixture are its source definition and the generated registry import.

### 9. Verify visual preservation

Check at least:

- a desktop viewport of `1440 × 900`;
- a mobile viewport of `390 × 844`.

The existing visual system, navigation structure, panels, typography, colors, and responsive behavior must remain intact. There must be no framework error overlay or relevant console error.

---

## Acceptance criteria

Test 01 passes only if every mandatory criterion below is satisfied:

- [x] A typed Agentbook domain model exists for Agent, Story, assertions/expectations, and currently necessary run types.
- [x] A typed `defineStory()` helper is the public Story authoring API.
- [x] Files matching `*.agent.stories.ts` are discovered by convention.
- [x] Adding the fixture requires no manual presentation-layer registration.
- [x] Discovery runs automatically before both `dev` and `build`.
- [x] The fixture appears under the Agent declared in its source file.
- [x] Sidebar counts are derived from discovered definitions.
- [x] The selected Story view renders fields from the discovered definition.
- [x] Existing demo Stories remain available after migration.
- [x] Presentation components do not contain fixture-specific ID behavior.
- [x] Duplicate Story IDs within one Agent are rejected.
- [x] Typecheck passes.
- [x] The discovery test passes.
- [x] The production build passes.
- [x] Desktop and mobile browser checks pass without relevant console errors or framework overlays.
- [x] No real LLM, authentication, database, billing, CLI, hosted registry, or external API was introduced.
